
\section{用户角色与运行环境}

\subsection{用户角色}

系统仅设\textbf{玩家}单一角色，无管理员后台。玩家可：浏览主菜单；选择关卡或跑图节点；在战斗中移动、打开技能面板、选择升级奖励；死亡后重启。未来若扩展存档，仍不改变“玩家”唯一角色定义。

\section{数据需求}

逻辑数据实体包括：\textbf{实体 Entity}、\textbf{角色 Character 行}、\textbf{子弹 Bullet 行}、\textbf{技能 Skill 行}、\textbf{效果 SkillEffect 行}、\textbf{跑图节点 RunNode}、\textbf{会话 GameSession}、\textbf{装配 SkillLoadoutState}。实体运行时状态存于 ECS 组件，配表行存于 \texttt{Data} 静态缓存，跑图图存于 \texttt{RunMapState}。

\section{接口需求}

\begin{enumerate}[label=\arabic*.]
  \item \textbf{配置接口}：\texttt{ensureGameConfigLoaded(): Promise<boolean>}，失败时返回 false 并日志告警；
  \item \textbf{战斗入口}：\texttt{MetaFlowController} 的 \texttt{onEnterCombat(payload?: CombatEnterPayload)}；
  \item \textbf{输入接口}：\texttt{ControlInputSource} 供 \texttt{ControlSystem} 查询方向；
  \item \textbf{UI 栈接口}：\texttt{UIStackManager.push(routeId)}、\texttt{pop()}；
  \item \textbf{Worker 协议}：\texttt{CombatWorkerComputeRequest/Response} 字段须版本兼容。
\end{enumerate}

\section{约束与假设}

\begin{itemize}
  \item 假设用户浏览器开启 JavaScript 与 WebGL；
  \item 假设开发阶段已执行配表同步脚本；
  \item 单机本地运行，无强联网要求；
  \item 2D 俯视角，不考虑 Z 轴复杂物理；
  \item 同屏实体规模在数百级，非 MMO 级。
\end{itemize}
