\chapter{性能优化与工程实践}
\label{chap:performance}

\section{性能目标与瓶颈}

H5 生存战斗的热点包括：大量实体更新与碰撞、预制体实例化引发 GC、主线程过载。Cantrell 等在 Unity 中实现物理人群模型时，同样关注计算开销与验证方法\cite{cantrell2018unity}；Bott 等使用游戏引擎工具链实现物理驱动人群移动\cite{bott2014unreal}。本项目在 2D H5 环境下采用对象池、Worker 卸载与逻辑暂停等手段应对类似瓶颈。

\section{对象池}

\texttt{BulletPool}、\texttt{MonsterPool} 按 \texttt{prefabPath} 分桶复用节点，复用前重置状态。将“每帧大量 instantiate/destroy”转为“峰值后复用”，降低 GC 停顿，与引擎资源管理最佳实践一致\cite{gregory2018game}。

\section{Web Worker 卸载}

\texttt{MonsterChaseSystem} 的追逐、分离、摆动为纯数值计算，可由 \texttt{CombatDataBridge} 提交 Worker 执行 \texttt{processCombatFrame}，主线程与 Worker 共享同一逻辑文件以保证一致性。实体数不足或 Worker 不可用时回退主线程。子弹碰撞因依赖 Laya 节点仍留主线程，与 McKenzie 等将游戏技术用于仿真但保留引擎交互层的思路类似\cite{mckenzie2008crowd}。

\section{其它优化}

\textbf{碰撞：} 使用距离平方比较。\textbf{暂停：} Tab 打开面板时 \texttt{GameSession.paused} 早退战斗系统。\textbf{配置：} 常量集中于 \texttt{defines}，配表一次加载。\textbf{未来：} 可探索 archetype 存储与空间划分 broad phase\cite{ullmann2025sydra}。

\section{绿色计算与兼容性}

降低平均 CPU 占用有利于终端节能。Worker 回退与双通道配表加载提升兼容性。浏览器或引擎升级后须回归 Worker 脚本路径与发布目录。
