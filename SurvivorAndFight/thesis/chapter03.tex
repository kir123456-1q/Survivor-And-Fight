\chapter{系统需求分析}

\section{可行性分析}

\subsection{技术可行性}

项目选用 LayaAir 3.x + TypeScript，团队已在仓库中完成 ECS 核心、战斗 Demo、元菜单、跑图生成、技能装配 UI 等模块的落地代码。引擎支持 2D 预制体实例化、帧循环与键盘输入；浏览器支持 Web Worker。配表通过 \texttt{tools/sync-config-to-bin.ps1} 同步至运行目录，技术路线可行\cite{kw_layaair_html5_engine,kw_typescript_large_scale}。

\subsection{经济与社会可行性}

作为毕业设计原型，主要成本为开发与测试人力，无大规模服务器依赖。游戏内容为奇幻战斗题材，须控制暴力表现尺度，并在用户协议与适龄提示方面符合相关法规\cite{kw_ethics_game_design}。长时间游戏可能带来视觉疲劳，应在 UI 与难度曲线上提供休息节点（如跑图 \texttt{Rest} 节点）。

\subsection{用例：局内战斗}

\textbf{参与者：}玩家。\\
\textbf{前置条件：}配表已加载，\texttt{SimpleEcsDemo.init()} 完成。\\
\textbf{主成功场景：}
\begin{enumerate}[label=\arabic*.]
  \item 玩家通过键盘/适配器输入移动，\texttt{ControlSystem} 写入 \texttt{Velocity}；
  \item \texttt{PlayerAutoCastSystem} 按装备技能与冷却自动施法；
  \item \texttt{BulletSystem} 生成子弹并检测与怪物碰撞，扣血并处理穿透/分裂/连锁；
  \item 怪物死亡给予经验，达到升级阈值时弹出 \texttt{RewardPanel}；
  \item 玩家按 Tab 打开技能面板，\texttt{GameSession.paused=true}，装配变更经 \texttt{SkillLoadoutSyncSystem} 写回战斗实体。
\end{enumerate}
\textbf{扩展：}玩家 hp 归零触发 \texttt{PlayerDeathSystem} 与重启面板。

\subsection{用例：元游戏进入战斗}

\textbf{主成功场景：}用户在 \texttt{MetaFlowController} 中选择关卡或跑图节点 $\rightarrow$ 回调 \texttt{onEnterCombat} $\rightarrow$ 显示战斗容器、初始化 Demo、启动 \texttt{CombatSurvivalTimer}（普通关/ Boss 关时长由 \texttt{COMBAT\_SURVIVE\_VICTORY\_SEC} 与 \texttt{BOSS\_COMBAT\_SURVIVE\_VICTORY\_SEC} 区分）。

\section{非功能性需求}

\subsection{性能需求}

\begin{itemize}
  \item 目标帧率：主流桌面浏览器 60 FPS（战斗高峰期允许短暂波动）；
  \item 同屏怪物数量：由 \texttt{MONSTER\_COUNT} 与波次系统控制，须配合对象池与 Worker 阈值；
  \item 配表加载：首次启动异步完成，不阻塞引擎启动超过可接受时间（须显示加载或延迟进入菜单）。
\end{itemize}

\subsection{可维护性需求}

模块边界与 OpenSpec \texttt{change-id} 对齐；静态配置仅存在于 \texttt{src/defines/*Define.ts}；禁止在 \texttt{Entry.ts} 的 \texttt{main} 中提交测试代码（引擎规范）。

\subsection{兼容性需求}

优先支持 Chromium 内核浏览器；Worker 不可用时 \texttt{CombatDataBridge} 回退主线程同步逻辑，保证功能一致\cite{kw_green_web_perf}。

\section{需求追踪矩阵}

项目采用 OpenSpec 任务清单（各变更目录下 \texttt{tasks.md}）追踪实现进度。例如 \texttt{add-bullet-hp-ui-verification} 覆盖血条绑定与阵营碰撞；\texttt{add-combat-skill-loadout-ui} 覆盖 13 技能 + 74 效果图标配表与拖拽 UI。毕业设计论文中的模块描述与仓库 \texttt{openspec/changes/} 目录一一对应，便于答辩时演示规格与代码一致性\cite{kw_spec_driven_dev,kw_project_management_agile}。
