\chapter{系统需求分析}
\label{chap:requirement}

本章在第~\ref{chap:related}~章技术选型基础上，给出 Survivor And Fight 的可行性论证、功能与非功能需求及验收口径，为第~\ref{chap:architecture}~章总体设计与第~\ref{chap:test}~章测试提供依据。需求描述以\textbf{可验证}为原则：每条 Must 级需求均可在代码或测试用例中找到对应实现或断言。

\section{可行性分析}

\subsection{技术可行性}

项目选用 LayaAir 3.x 与 TypeScript，已实现轻量 ECS、配表战斗、元菜单、DAG 跑图、技能装配 UI 及对象池/Worker 优化模块。引擎提供 2D 预制体、\texttt{frameLoop} 与输入封装；Chromium 内核浏览器支持 WebGL2 与 Web Worker。SyDRA 等研究表明，理解引擎子系统边界有助于控制演化成本\cite{ullmann2025sydra}；Cantrell 等验证了在商业引擎上叠加领域逻辑（人群/怪物运动）的可行性\cite{cantrell2018unity}。

\textbf{已具备能力}：\texttt{ConfigBootstrap.ensureGameConfigLoaded} 双通道加载配表；\texttt{isGameConfigReady} 作为战斗入口闸门；单元脚本覆盖 ECS 核心、公式解析与属性修饰器。\\
\textbf{主要风险}：同屏千怪帧率、Worker 与主线程逻辑一致性、UI2 拖拽命中——已通过第~\ref{chap:test}~章五波实验与 T-F-05/06 等用例部分缓解。\\
\textbf{结论}：在毕业设计周期内交付可运行原型并完成配套论文，技术路线可行。

\subsection{经济与社会可行性}

作为教学原型，主要成本为开发与测试人力，无服务器与支付链路。游戏为奇幻战斗题材，须控制暴力表现、提示合理游戏时长；跑图休息节点提供节奏缓冲。未采集用户敏感信息，符合单机演示定位。

\section{用户角色与运行环境}

\subsection{用户角色}

系统仅设\textbf{玩家}单一角色：浏览主菜单、选关或跑图、局内移动与构筑、死亡后重启。无管理员后台；未来若扩展存档，不改变“玩家”唯一角色定义。

\subsection{用例：局内战斗}

\textbf{参与者}：玩家。\textbf{前置条件}：\texttt{isGameConfigReady()==true}，\texttt{SimpleEcsDemo.init()} 完成。\textbf{主成功场景}：（1）输入移动；（2）\texttt{PlayerAutoCastSystem} 自动施法；（3）子弹碰撞并应用穿透/分裂/连锁；（4）击杀获经验并升级；（5）Tab 打开技能面板，\texttt{GameSession.paused=true}，装配后恢复。\textbf{扩展}：\texttt{hp}$\leq$0 时显示重启面板。对应第~\ref{sec:scenarios}~节场景一、二。

\subsection{用例：元游戏进入战斗}

用户在跑图或选关界面确认节点，\texttt{MetaFlowController} 触发 \texttt{onEnterCombat(payload)}；\texttt{Main} 显示战斗容器、\texttt{demo.init()}，\texttt{CombatSurvivalTimer} 启动；Boss 节点载荷可携带更长胜利时间。

\section{功能需求详细说明}
\label{sec:func-detail}

\subsection{ECS 核心}

须提供实体创建/销毁 API，销毁时移除全部组件；同类型组件不可重复挂载；系统按 \texttt{input/logic/render} 分组与优先级确定性调度；支持按组件类型遍历及命名筛选器查询\cite{gregory2018game}。

\subsection{战斗与技能}

玩家须具备 hp/maxHp 与可溯源 modifier。技能由配表定义冷却与 effect 列表；至少三个装备栏独立冷却。效果类型覆盖 \texttt{bullet}、\texttt{modifier\_*}、\texttt{direct\_damage}；子弹带阵营，仅对敌对阵营生效；连锁半径有界，避免无界遍历\cite{helbing2000panic}。

\subsection{怪物、元游戏与 UI}

怪物在玩家周围环带生成并保持最小间距；追逐、接触伤害、离屏回收；击杀给予经验（含等级加成项）。跑图每局三幕 DAG，仅沿已解锁邻接边前进；\texttt{validateActReachBoss} 保证可达。全屏界面经 \texttt{UIStackManager}；Tab 暂停战斗；拖拽区分技能/效果槽；血条与升级面板实时反馈\cite{heijstek2011empirical}。

\section{非功能性需求}

\textbf{性能}：目标稳定 60 FPS；同屏规模由 \texttt{MONSTER\_COUNT} 与波次控制；对象池与 Worker 按第~\ref{sec:perf-design}~节启用。\\
\textbf{可维护性}：模块边界与第~\ref{chap:architecture}~章一致；静态常量集中于 \texttt{defines}。\\
\textbf{可靠性}：Worker/配表/跑图失败时回退路径见第~\ref{sec:reliability}~节。\\
\textbf{兼容性}：优先 Chromium；Worker 不可用时 \texttt{computeSync} 主线程回退\cite{cantrell2018unity}。

\section{数据、接口与约束}

\textbf{逻辑数据实体}：运行时 ECS 组件；配表行（\texttt{Character}、\texttt{Skill}、\texttt{SkillEffect}、\texttt{Bullet}）；\texttt{RunMapState} 图结构；\texttt{GameSession}、\texttt{SkillLoadoutState}。

\textbf{关键接口}：（1）\texttt{ensureGameConfigLoaded(): Promise<boolean>}；（2）\texttt{onEnterCombat(payload?)}；（3）\texttt{ControlInputSource}；（4）\texttt{UIStackManager.push/pop}；（5）\texttt{CombatWorkerComputeRequest/Response} 字段版本兼容。

\textbf{约束与假设}：浏览器启用 JavaScript 与 WebGL；开发阶段已执行 \texttt{sync-config-to-bin.ps1}；单机本地运行；2D 俯视角；同屏数百实体级，非 MMO 规模。
