# 技能效果解析、局内特效需求与怪物/房间设计（文档稿）

> 本文档仅作策划与设计说明，**不绑定当前代码实现**；数据依据仓库内现有配表与系统行为归纳。

---

## 一、当前设计中的「技能 / 效果」来源

| 来源 | 配置位置 | 作用域 |
|------|-----------|--------|
| 技能 + 技能效果行 | `config/skill_table.json`、`config/skill_effect_table.json` | 局内施放（ECS `SkillSystem`） |
| 战斗升级效果 | `config/upgrade_effect_table.json` | 局内数值（攻速、伤害、多发、命中分裂等） |
| 法杖效果池（规划） | `docs/config/wand_effect_pool_table.json` + `INTERFACES.md` 中法杖效果行 | 按大关阶段 `min_stage` 与玩家等级过滤的构筑池 |

`SkillSystem` 当前对单条 effect 行的解析要点：

- `effect === "bullet"` 且存在 `bulletSlot`：生成子弹（方向由 `target`：`auto` / `simple` 决定）。
- 否则若 `effect === "damage"`：对解析到的目标直接扣血（`params` 公式）。
- 玩家侧还会叠加 `UpgradeState`（射速倍率、伤害倍率、`multiShotExtra`、`onHitSpawnCount` 等）。

以下「是否需要局内特效」指：**除已有子弹预制体表现外**，是否还需要额外的施法/命中/范围/状态类 **VFX（粒子、光效、屏幕反馈等）**。

## 二、逐项效果：是否需要局内特效 & 建议特效形态

### 2.1 已实现：技能效果表（`skill_effect_table`）

| 效果 ID / 类型 | 逻辑摘要 | 是否需要额外局内特效 | 建议特效（若做） |
|----------------|----------|----------------------|------------------|
| `player_auto_shot_effect_1`（`bullet` + `auto`） | 向自动锁定目标方向生成 `bulletSlot` 子弹 | **弱需求**：子弹本体已承担主视觉 | 可选：枪口/角色侧 **短促火花**（0.05–0.12s）、**极细弹道拖尾**（与子弹表美术统一） |
| （扩展）`damage` + `auto`/`simple` | 无子弹，直接公式伤害 | **强需求**：无弹道时玩家难以感知命中 | **锁链/光束**连 caster→目标、`hit_flash`、受击 **飘字** 或材质闪白 |

### 2.2 已实现：升级效果（`upgrade_effect_table`）

这些在选中升级项**生效瞬间**与**持续状态**上可考虑反馈，不属于传统「技能读条」，但对构筑感很重要。

| effectType | 是否需要局内特效 | 建议特效 |
|--------------|------------------|----------|
| `fire_rate` | 建议有 | 武器/身体 **短暂加速流光**（环身 0.2s）或 UI 层 **攻速条脉冲** |
| `damage` | 建议有 | **武器附魔色**切换一帧 + 下一次开火略增 **枪口光晕** |
| `multi_shot` | 建议有 | **扇形示意线**（仅本地预测 0.15s，不挡视野）或双发 **重叠残影** |
| `on_hit_spawn` | **强需求**（分裂弹辨识度） | 命中点 **小型径向爆发** + 子子弹生成 **微型环状冲击** |

### 2.3 规划：法杖效果池类别与标签（`wand_effect_pool_table`）

表中 `category` 与 `requires_tags` 描述的是**未来法杖构筑效果**；与 `WandEffectRow.effect_type`（如 split、explosion、chain）对应时，局内特效需求如下。

#### 类别 `melee_orbit`（近战环绕）

| 典型标签 / 行为 | 局内特效需求 | 建议 |
|-----------------|--------------|------|
| `orbit` | **强** | 环绕体 **轨迹带**、旋转 **风圈**、与敌人重叠时 **切割火花** |
| `close_range` | 中 | 近身 **气浪**、敌人进入范围 **警示圈**（可极淡） |
| `multi_hit` | 中 | 每次命中 **小星爆**（防视觉疲劳需限频） |
| `burst` | 强 | 短爆发 **亮度上冲** + **残影缩放** |
| `execute` | 强 | 低血目标 **处决标记**（骷髅/裂纹）、击杀 **竖直光柱** |

#### 类别 `ranged_shot`（定向射击）

| 典型标签 / 行为 | 局内特效需求 | 建议 |
|-----------------|--------------|------|
| `projectile` / `single_shot` | 弱～中 | 与子弹美术统一即可；可加 **蓄力点** |
| `split` | **强** | 分裂帧 **棱镜折射**、子弹道 **色差** |
| `explosion` | **强** | **范围圈**（落地前预警）+ 爆心 **火球/烟尘** + 边缘 **震荡波** |
| `chain` | **强** | 链跳 **电弧**（分段贝塞尔）、每跳 **触点闪光** |
| `burn` | 中～强 | 目标 **持续余烬**、地面 **小火苗**（受性能预算限制） |

#### 类别 `ranged_random`（随机/散射）

| 典型标签 / 行为 | 局内特效需求 | 建议 |
|-----------------|--------------|------|
| `random` / `scatter` | 中 | 发射前 **准星抖动粒子**、弹道 **轻微曲线拖尾** |
| `multi_target` | 中 | 多目标时 **短暂锁定线**（多段同时淡出） |
| `ricochet` | **强** | 反弹点 **镜面高光**、**折线轨迹**高亮一帧 |
| `smart_target` | 中 | 选中目标 **弱聚光灯**或 **UI 三角标记** |

### 2.4 小结：优先级（便于排期）

1. **P0（无则玩法难读）**：直接 `damage`、爆炸、连锁、分裂、处决、环绕持续伤害圈。  
2. **P1（构筑爽感）**：升级获得时的 fire_rate / multi_shot / on_hit_spawn、燃烧 DOT。  
3. **P2（ polish）**：单发子弹的枪口火花、随机散射的抖动提示等。

## 三、强度阶梯：与「三大关」对齐

与跑图规格一致：每局 **三个大关（Act）顺序推进**；法杖池使用 `min_stage` 1 / 2 / 3 与玩家等级门槛，此处 **怪物与房间** 采用同一阶梯：

| 阶梯 | 对应 | 玩家预期状态 | 怪物设计原则 |
|------|------|----------------|--------------|
| **第一大关** | `min_stage === 1` | 基础输出与走位学习 | 血量与伤害 **低**、机制 **单一**、密度 **中** |
| **第二大关** | `min_stage === 2` | 已有若干升级与资源 | **组合威胁**（远近、快慢、封锁走位） |
| **第三大关** | `min_stage === 3` | 构筑成型 | **高数值或强机制**、精英词缀感、Boss 多阶段 |

## 七、房间放怪逻辑（与跑图节点类型对齐）

跑图节点类型（规格）：`Combat`、`Elite`、以及大关终端 Boss 战等。以下用 **「房间模板」** 描述遭遇组成；实际实现可用 `payloadId` 映射模板 ID。

### 7.1 全局规则

- **出生**：与现有规格一致，小怪批量生成时使用 **四角随机出生点**；Boss/大型单位改用 **边中点或专用出生锚点**（文档约定，落地时配表）。
- **威胁预算**：每个房间有隐藏「预算点」；小怪占 1 点，精英占 8～12 点，Boss 不占点（单独关卡）。
- **大关系数**：Act1 预算 ×1.0；Act2 ×1.35；Act3 ×1.7。同预算下 Act3 更少怪但单体更强。
- **组合禁忌（软规则）**：同房间避免「仅 M09+M10」这类高闪避+长手纯折磨组合超过连续两房；Act1 禁止 E04/E05。

### 7.2 普通战斗节点 `Combat`

| 房间模板 ID | 适用 Act | 组成逻辑 |
|-------------|----------|----------|
| `C_SWARM` | 1 | 随机 2 种 Act1 小怪，总数 12～18，均匀四角分批刷 |
| `C_MIXED_A` | 1～2 | 1 种 Act1 小怪 + 1 种 Act2 小怪（8+6），第二波补 4 只快怪 |
| `C_RANGED` | 2 | M03/M08 占比 ≥50%，其余用 M05 牵制，预算内补 M06 |
| `C_PRESSURE` | 2～3 | M07 至多 3 只且错开出生时间；其余填 M05/M10 |
| `C_ACT3_CORE` | 3 | 仅 M08/M09/M10 中抽 2 种，总数↓但攻击频率↑ |

### 7.3 精英节点 `Elite`

| 房间模板 ID | 适用 Act | 组成逻辑 |
|-------------|----------|----------|
| `E_SOLO` | 1 末、2 | 1 个 E01～E03（按 Act 权重：Act1 仅 E01；Act2 增加 E02/E03）+ 少量 Act1 小怪护阵（4～6） |
| `E_SUPPORT` | 2～3 | 1 精英（E02/E03/E04）+ 与精英机制 **协同** 的小怪（如 E02 配 M03；E04 配 M08） |
| `E_ACT3` | 3 | E04 或 E05 二选一；若 E05 则第一波必出 M10 干扰清召唤物 |

### 7.4 Boss 房（大关终端）

- **唯一 Boss**：每大关终端仅 **B01 / B02 / B03** 中对应关卡的一只；不入普通预算池。  
- **入场小怪**：B01 带 M01/M03；B02 带 M06；B03 带 M09 或短波 M10，用于阶段转场压迫感。  
- **精英客串**：仅 B02 P2 允许「弱化双目标」；不在 B01/B03 中插入完整精英预算，以免读条重叠。

### 7.5 与法杖池 `min_stage` 的协同（设计意图）

- Act1 房间以 **少机制、多数量** 为主，配合池中 `min_stage: 1` 的 common 构筑形成「易学难精」。  
- Act2 引入 **地面与节奏**（毒环、雷反、AOE 圈），配合 `min_stage: 2` 的 rare 效果（分裂、爆炸、弹跳）形成解法。  
- Act3 压缩安全区与 **召唤/隐身**（E05、M09），配合 `min_stage: 3` 的 epic（链、复合爆炸燃烧）作为终局表达。
