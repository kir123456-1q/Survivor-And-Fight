## 第 3 页｜研究背景与意义

### 文字内容
- H5 游戏普及：链接即玩、跨端发布，但浏览器 **单主线程** 限制明显
- Survivor-like 玩法特征：自动攻击、怪潮压力、局内构筑 + Roguelite 元流程
- 痛点：同屏实体多 → 碰撞/刷怪/界面刷新挤占帧预算；深继承 OOP 难维护
- **选题意义**：验证轻量 ECS + 数据驱动 + 性能手段在 H5 生存战斗中的可行性
- **交付物**：可跑通「菜单 → 跑图/选关 → 战斗 → 升级装配 → 死亡重启」的原型

### 图表内容
- **对比表**（简表 3 列）：

| 维度 | 传统 OOP 预制体方案 | 本项目 ECS 方案 |
|------|---------------------|-----------------|
| 扩展方式 | 继承子类 | 增组件 / 增 System |
| 同屏规模 | 实例化 GC 压力大 | 对象池 + Worker |
| 数值迭代 | 改代码 | JSON 配表 |

- **小插图**：吸血鬼幸存者类玩法示意（自动攻击 + 怪海，可用示意图）

## 第 10 页｜MVC UI 与战斗协同

### 文字内容
- **UI 架构**：MVC 变体 — Model 来自 ECS/跑图状态；View 只管布局；Controller 管路由

- **拖拽**：SkillDragService 顶层代理 + SkillSlotHitTest 区分装备栏/效果槽

## 第 11 页｜性能优化方案

### 文字内容
- **对象池**：BulletPool / MonsterPool 按预制体路径分桶，抑制 instantiate/destroy GC 尖峰
- **Web Worker**：实体数 ≥ 阈值时，追逐/分离/摆动卸载；主线程与 Worker 共用 `combatWorkerLogic.ts`
- **回退路径**：Worker 失败 → `computeSync` 主线程补算；子弹碰撞仍留主线程
- **逻辑冻结**：paused 时各战斗 System 早退，Tab/死亡/胜利共用同一开关
- **渲染侧**：TextureAtlasService 动态图集合批；BulletHitTest 用距离平方避免开方

## 第 13 页｜性能测试与数据解读

### 文字内容
- **环境**：1920×1080，LayaAir IDE 内置 Chromium，Level3 五波脚本
- **规模曲线**：怪物 10 → 100 → 1000，FPS 由 58.62 降至 15.14
- **动态图集**：第 3 波千怪 FPS 13.32 → 15.10（约 +13.4%）
- **对象池消融**（第 4–5 波同窗）：P95 76.50 ms → 48.60 ms（约降 36.5%）
- **结论**：池化主要削 P95 尖峰；图集改善绘制；Worker 参与 1–3 波追逐重算

## 第 15 页｜主要创新点与工程特色

### 文字内容
1. **轻量 ECS**：EcsWorld 驱动玩法 tick；ViewComponent 只绑 Laya 节点；业务不直接调引擎 API  
2. **性能组合拳**：对象池 + Web Worker + 动态图集 + paused 逻辑冻结，均可开关做消融  
3. **UI 与战斗协同**：UIStackManager 管全屏栈；Tab 装配与 `GameSession.paused` 统一切断战斗 tick  
4. **数据驱动 + 可验证**：JSON 配表 + `*.verify.ts` 脚本 + 需求—测试追溯表  
5. **可靠性设计**：配表/Worker/跑图/预制体均有降级路径，避免白屏  

### 图表内容
- **五角星或三环图**：创新点 1–5 围绕中心「H5 Roguelite 可维护原型」
